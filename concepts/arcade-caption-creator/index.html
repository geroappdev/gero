    Arcade: Caption Creator

    Caption Creator lets you compose a multi-clip story from your library and have an AI write captions that match what's on screen — turning a sequence of fragments into a narrated, captioned mini-story.

    Experimental — use at your own risk

    The AI side of Caption Creator has only just been integrated and is not fully tested yet. It works reasonably well, but expect rough edges. The tag timeline and frame description features described below are in-progress concepts that are still being refined. Nothing here can damage your library, but results will vary.

    What is Caption Creator?

    You build a story out of clips from your library and arrange them in order. For each clip, an AI language model writes a caption that fits the visuals. The result is a captioned story you can play back.

    The AI needs two kinds of understanding to do this well:

    1. What's in each frame — produced by a vision model that tags the frames of your clips (see Frame tagging).
    2. How to write the caption — produced by a text model that turns those visual facts into a caption.

    Both run locally through Ollama. Nothing is sent to a cloud service.

    Setting up the AI (Ollama)

    Step 1 — Install and run Ollama

    Install Ollama on a machine that GERO can reach over HTTP (your own PC, or another machine on your network). By default Ollama listens on http://localhost:11434.

    Pull three models — a text model, a vision model, and an embedding model:

    # TEXT — writes the captions (pick one your hardware can run)
ollama pull llama3.1

# VISION — looks at your clips and describes each frame. JoyCaption is purpose-built for detailed,
# natural descriptions and gives the best "Describe all videos" results:
ollama pull aha2025/llama-joycaption-beta-one-hf-llava:Q5_K_M
#   ↳ Q5_K_M is a good balance; Q4_K_M is lighter, Q6_K / Q8_0 are heavier + sharper. A general
#     vision model like llava also works as a fallback:  ollama pull llava

# EMBEDDING — turns those descriptions into vectors for clip matching. nomic-embed-text is the tried-
# and-tested choice:
ollama pull nomic-embed-text

    The AI models power the library-wide content matching

    The Describe pass (vision model) and the embeddings it produces (embedding model) drive the smart clip-matching across the arcade. Caption Creator and QuizTime match clips by embedding similarity — they need both a vision and an embedding model. Follow the Beat is different: it matches on motion tempo + your tag/actor filter only, so it needs no AI models at all. See Local analysis tools for the motion side (Python), which pairs with this.

    Hardware matters

    Larger models produce better captions but need more RAM/VRAM and run slower. Start with a smaller model, confirm the flow works, then scale up.

    Step 2 — Point GERO at Ollama

    In GERO, go to Settings → AI provider and:

    1. Set the provider to Ollama
    2. Add a server with the base URL of your Ollama instance (e.g. http://localhost:11434)
    3. Tick the capabilities that server should handle — text, vision, and/or embed. You can split these across multiple machines if you have them
    4. Choose the default story model (the text model that writes captions)

    If GERO can reach the server, the model dropdowns fill in automatically from what Ollama has pulled. If it can't reach it, you'll get a free-text box instead — double-check the URL and that Ollama is running.

    Step 3 — Configure frame tagging

    Go to Settings → Frame tagging. This controls the "Analyze frames" job, which is how GERO understands the visuals of your clips:

    • Vision model — the Ollama vision model that tags each sampled frame
    • Tag vocabulary — whether the model may only pick from a video's own tags, or from all tags
    • Frame resolution / interval — how large each sampled frame is, and how often frames are sampled. Denser sampling is more accurate but slower

    The per-frame tags this job produces become the visual context the caption model reads.

    In-progress concepts

    These are the experimental knobs being used to push caption quality. They live under Settings → Arcade (Caption Creator) and Settings → AI provider, and their behaviour may change between releases.

    Concept What it does
    Frame description (detailed beats) Feeds the caption model a per-frame breakdown of each clip, so captions can reference what happens moment to moment rather than just the clip as a whole. Can be limited to shorter clips to keep prompts manageable.
    Tag timeline Feeds the model a per-second timeline of which tags are active, giving it a sense of timing — when something starts, peaks, and ends within a clip.
    Time pins Lets the model anchor a caption to an exact second in a clip.

    These are deliberately experimental. If captions come out odd, try toggling them off and regenerating.

    Using Caption Creator

    1. Create a level — pick the clips for your story and arrange them in order
    2. Analyze frames — run frame tagging so the AI knows what's in each clip
    3. Generate captions — the text model writes a caption per clip from the visual context
    4. Review and tweak — edit any caption by hand; regenerate individual clips as needed
    5. Play — run the level to see your story with its captions

    It's a starting point

    Caption Creator is the newest game in GERO and the AI behind it is early. Treat generated captions as a draft you refine, not a finished product — and expect this whole flow to get noticeably better over the next releases.
