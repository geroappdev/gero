    Privacy policy

    Overview

    Gero is designed with privacy at its core. Your data belongs to you — always.

    Privacy first

    Gero runs entirely on your own hardware — the Windows PC you installed it on. This means:

    • All your data stays on your own machine
    • Gero does not send your data to external servers
    • No tracking or analytics are built into the application
    • You have complete control over your installation

    There is exactly one moment when Gero itself talks to a server, and you have to press a button to cause it. It is written out in full below, because a privacy promise with an unmentioned exception in it isn't worth much.

    The one exception: the update check

    Gero can check whether a newer version of itself has been released. This is the only request Gero ever makes on its own behalf, and here is exactly what it is:

    • It only happens when you click it. The check runs when you press Check for updates in Settings → Updates, and at no other time. Gero never checks on a schedule, at startup, or in the background.
    • One server, and it's your own supporter downloads server. The request goes to the downloads page you got your key from (gero-downloads.geroappdev.workers.dev). Nowhere else.
    • It carries only the update key you pasted in yourself. Nothing else is attached. The key's only job is to prove you're a supporter.
    • It asks one question: "is there a newer version?" Nothing about your library, your tags, your videos, your settings, your installation, how you use Gero, or the machine it runs on is sent — not even the version you're currently running. The comparison with your version happens on your machine, after the answer comes back.
    • No key, no request. Without a saved update key the check cannot run at all, so if you never enter one, Gero never contacts anything.

    If the answer is yes, Gero shows you the version and its release notes and waits for you to confirm. Only then does it download that release — from the same server, with the same key, and again sending nothing else.

    Gero also remembers the version number and release notes locally, so it can put a quiet reminder on the homepage if you didn't install the update. That reminder is drawn from the answer you already fetched — it does not go online again.

    Everything else on this page still holds without qualification: no telemetry, no analytics, no usage reporting, no crash reporting, and no background communication of any kind.

    Storage of the update key

    The key is stored encrypted in your own local database and is never shown back to you — the settings page only reports whether a key is set. It is only ever sent to the downloads server described above.

    What's stored locally

    All data is stored locally:

    • Videos and media — In your configured library path
    • User accounts — Credentials are securely hashed
    • Settings — In your local database
    • Fragments and thumbnails — Stored locally
    • Metadata — Tags, actors, and video information

    We do not collect anything

    • No usage analytics
    • No telemetry data
    • No crash or error reporting
    • No device identifiers, fingerprinting or profiling
    • No advertising trackers
    • No third-party cookies

    Nothing about you, your library or how you use Gero leaves your machine. The one outbound request Gero makes — the manual update check — carries your update key and nothing else. See the one exception above.

    Third-party tools

    Gero uses these tools locally on your own machine. The last row isn't a tool but the update check — listed here so the picture is complete:

    Tool Purpose Privacy impact
    yt-dlp Download videos from external sources Only connects when you request a download
    FFmpeg Process videos All processing happens locally
    Ollama (optional) Local AI — frame descriptions + embeddings for the arcade games Runs on your own machine (or another PC on your network you point Gero at); nothing goes to a cloud AI service
    Python (opencv/librosa, optional) On-device motion + beat analysis Runs locally; only reaches out once to fetch the packages when first installed
    Update check (optional) Ask the supporter downloads server whether a newer Gero release exists Only runs when you press Check for updates, and only if you saved an update key; sends the key and nothing else — no library, usage or machine data

    None of these ever send your videos, your metadata or your usage anywhere.

    Security

    • Passwords are securely hashed using industry-standard algorithms
    • Sessions are managed with secure cookies
    • HTTPS is supported via reverse proxy (recommended for remote access)
    • All data remains on your machine

    Your rights

    Since Gero runs on your machine, you have complete control:

    • Full data ownership — Everything is yours
    • Export anytime — Back up your database and media
    • Delete anytime — Remove data or the entire application
    • Access control — Decide who can access your instance

    GDPR

    Since Gero runs locally:

    • You are the data controller
    • You determine how data is processed
    • None of your content, metadata or usage is shared with us (the software developers)

    The only thing that ever reaches us is your update key, and only in the moment you press Check for updates. It tells the downloads server that a valid supporter asked for the current version number. You can stop even that by removing the key in Settings → Updates.
